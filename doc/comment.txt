1. Introduction                                        *comment-introduction*
                                                                     *comment*

comment.nvim highlights and searches `TODO`/`FIX`/`HACK`/`NOTE` comments,
and lets you insert them with one command.

==============================================================================
2. Requirements                                        *comment-requirements*

Neovim >= 0.10, since the plugin relies on `vim.system`, `vim.filetype.get_option`,
and `vim.uv`, all added in that release.

Project search (|:TodoQuickFix|, |:TodoTelescope|) requires ripgrep (`rg`)
on `$PATH`. |:TodoTelescope| additionally requires
https://github.com/nvim-telescope/telescope.nvim to be installed; without
it, a warning is shown instead of erroring.

==============================================================================
3. Setup                                                      *comment-setup*

comment.nvim does nothing until >

    require('comment').setup(opts)

<
`opts` is optional and every field has a default:

    comments_only   (boolean, default `false`)
                    Restrict keyword highlighting to TreeSitter comment
                    nodes. Falls back to highlighting everything if no
                    parser is available for the buffer's filetype. Does
                    not affect |:TodoQuickFix| / |:TodoTelescope|, which
                    always search the whole file via ripgrep.

    line_hl_group   (boolean, default `false`)
                    Tint the whole line containing a match, not just the
                    keyword. Each keyword uses its own line highlight
                    group (`CommentKeywordTodoLine`, etc.), separate from
                    the keyword's own foreground group, so the line tint
                    can be overridden independently. When two keywords
                    match on the same line, exactly one of them sets the
                    line highlight — which one is unspecified (governed
                    by internal keyword iteration order, not position in
                    the line).

    signs           (table<string, string>, default `{}`)
                    Per-keyword sign-column glyph overrides, keyed by
                    keyword name, e.g. `{ TODO = 'T' }`. Every keyword has
                    a default single-letter sign (`T`/`N`/`F`/`H`) shown
                    with the keyword's own highlight color; unset entries
                    keep their default. An override must be 1-2 display
                    cells (Neovim's own `sign_text` requirement) or it is
                    ignored with a warning and the default letter is used
                    instead. The sign only renders when 'signcolumn' is
                    `yes` or `auto`; the plugin never sets 'signcolumn'
                    itself. When two keywords match on the same line, exactly
                    one of them sets the sign — which one is unspecified
                    (governed by internal keyword iteration order, not
                    position in the line).

4. Commands                                                *comment-commands*

                                                              *:TodoQuickFix*
:TodoQuickFix   Search the project with ripgrep for `TODO`/`FIX`/`HACK`/
                `NOTE` and populate the quickfix list with the results.

                                                              *:TodoTelescope*
:TodoTelescope  Same search as |:TodoQuickFix|, shown in a Telescope picker.

                                                                *:TodoInsert*
:TodoInsert     Prompt for text and insert it as a `TODO` comment on a new
                line below the cursor, indented to match the current line
                and formatted with the buffer's 'commentstring'. No default
                keymap is bound; map it yourself, e.g.: >

    vim.keymap.set('n', '<leader>td', '<cmd>TodoInsert<cr>')

<
                                                     *comment.todo_quickfix()*
require('comment').todo_quickfix({keywords}, {title})
                Search the project with ripgrep for {keywords} (a list of
                strings) and populate the quickfix list with the results,
                same "no matches" handling as |:TodoQuickFix|. {title} is
                an optional string used as the quickfix list title.
                Public so users have a supported way to bind their own
                keys, e.g.: >

    vim.keymap.set('n', '<leader>tt', function()
        require('comment').todo_quickfix({ 'TODO' }, 'TODO search')
    end)

<
                                                            *comment.insert()*
require('comment').insert.todo()
require('comment').insert.note()
require('comment').insert.fix()
require('comment').insert.hack()
                Same as |:TodoInsert|, one function per keyword: prompt for
                text and insert it as a `TODO`/`NOTE`/`FIX`/`HACK` comment on
                a new line below the cursor. No default keymap is bound; map
                whichever you want, e.g.: >

    vim.keymap.set('n', '<leader>tn', require('comment').insert.note)

<
